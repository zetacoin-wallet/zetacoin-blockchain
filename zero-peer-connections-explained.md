Zero peers means the wallet cannot reach any other node, so it cannot download blocks. The cause is almost always local: a firewall blocking port 17333, a VPN, a network that filters unusual ports, or an outdated build with dead seed nodes. Fix the path out, restart, and the counter climbs.

## What a peer is and why the number matters

A peer is another node running the same software. The client asks peers for blocks and transactions, and with no peers it has nobody to ask. Everything you see in the wallet  -  height, balance, confirmations  -  depends on that conversation.

The number is not a score, and a low count is not a warning about the chain's health or about your balance. Fourteen peers is healthy; forty is fine; one is a warning sign rather than a disaster, because a single good peer can still deliver the whole chain given time. What matters is that the count is above zero and stays there.

| Peer count | What it means |
| --- | --- |
| 0 and staying | outbound traffic blocked, or no reachable nodes |
| 0 briefly at start | normal during discovery |
| 1 to 3 | working, on a thin connection |
| 8 and above | healthy |
| rising then dropping to 0 | network filtering or an unstable connection |

The full walk-through, with the checks in order, is in [Zetacoin Wallet Not Syncing: Step-by-Step Fix](https://github.com/zetacoin-wallet/zetacoin-blockchain/blob/main/wallet-not-syncing-walkthrough.md).

## The five causes, in order of likelihood

Firewall first, because it is the most common and the easiest to check. A client that was never allowed through the system firewall shows zero peers on every start and gives no other symptom.

Network second. A VPN, an office network or a hotel wireless can block the port entirely. The tell is that the same wallet finds peers on a different connection.

Build third. Older releases carry seed nodes that may no longer answer, which produces zero peers on a perfectly good network.

Data fourth. A wallet following a retired chain may connect to peers and still show nothing useful, which looks like a peer problem but is a chain problem.

Machine fifth. A clock that drifts, a full disk or exhausted memory can all stop the client from maintaining connections, even though the network is fine.

## Fixing the firewall properly

Allow the application, not just the port. Modern firewalls track per-application rules, and a port exception without an application rule still leaves the client blocked on some systems.

On Windows, the first-launch prompt is the moment to allow it; if it was dismissed, the rule can be added manually for both private and public networks. On macOS, approve the app in the firewall settings. On Linux, check the outbound policy and any rules that drop the port.

Then restart the client, because a running process may still hold the old state.

For the background behind this step, [Zetacoin Ports, Nodes and zetacoin.conf](https://github.com/zetacoin-wallet/zetacoin-blockchain/blob/main/ports-nodes-and-conf-settings.md) covers the same ground in more detail.

## When the network is the blocker

Test on a different connection before changing configuration. A phone hotspot is the quickest test available and it answers the question in a minute: if peers appear there, the original network is filtering traffic, and no amount of wallet configuration will change that.

If the network is the problem, options are limited and none involve the wallet. Use a connection that permits the port, or a VPN that does. On a network you control, opening outbound traffic on 17333 is the durable fix.

## Adding nodes as a workaround

When the network permits traffic but discovery is thin, an explicit node list gives the client somewhere to start. Add `addnode=` entries to `zetacoin.conf` in the data directory and restart.

This helps a wallet on a marginal connection more than it helps a blocked one. If the port is blocked, no list of addresses will produce a peer, because the connection attempt never leaves the machine.

## Checking the build

Compare the version in the client with the newest entry on {{RELEASE}}. If the client is older, install the current release  -  dead seed nodes in an old build look exactly like a network fault and are fixed by the update rather than by configuration.

Updating is also the answer when peers connect and immediately disconnect, because connection handling has changed across releases.

## Reading the log instead of guessing

The client's log records peer attempts and their outcomes. A log full of connection timeouts points at the network; a log that shows peers connecting and then dropping points at the build or the chain data; a log with no peer activity at all points at the firewall.

That single file converts a guessing game into a diagnosis. It is also the first thing to attach to a support request, because it contains the evidence.

## Peers, staking and the wallet that looks idle

A wallet with zero peers still shows a balance and still accepts a passphrase, which is why people keep using it and wonder later why nothing changed. Staking in that state does nothing, because staking means producing a block that other nodes accept, and a node on its own has nobody to accept anything.

If the staking indicator is grey and the peer count is zero, fix the peers first. {{ARTICLE:how-to-stake-zetacoin-coins}} covers the staking requirements in order, and it starts with a synced wallet for exactly this reason.

## Common questions

### Is zero peers dangerous?

No. It means the wallet is not syncing, not that coins are at risk. Nothing in the wallet file changes while peers are absent.

### How many peers should I have?

Around fourteen is typical and healthy. Any number above zero with a rising height is working.

### Do I need port forwarding for peers?

No. Forwarding 17333 lets peers reach you and improves the network, but the client finds peers without it.

### Why did peers drop to zero after it worked?

Usually a network change  -  a laptop moving between Wi-Fi networks, a VPN reconnecting, or a router reboot. Check the connection before touching the wallet.

## The fix in one line

Allow the app through the firewall, restart, and if the count stays at zero test another network; then update from {{RELEASE}}.
